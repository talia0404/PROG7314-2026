# 🎟️ 2. What Is a QR Parking Pass?

A QR code is simply a machine-readable representation of data.

For ParkSmart, the QR code should contain a token that identifies the reservation.

Conceptually:

```text
Reservation
-> Secure QR Token
-> QR Image
```

The QR code itself does not automatically prove that:

```text
Reservation exists

Reservation is active

Reservation belongs to today

Driver has not already checked in
```

Those checks belong to the API.

---

# 🚫 3. Do Not Treat the QR Code as the Security Decision

This would be incorrect:

```text
QR scanner reads value
-> Android says "Valid"
-> Driver enters
```

The scanner only tells Android:

```text
This is the value stored inside the QR code.
```

ParkSmart still needs to ask:

```text
Does this token exist?

Is the reservation valid?

Is the reservation active?

Has it already been used?

Is the user scanning it authorised?
```

The correct flow is:

```text
QR Scanner
-> Reads token
-> Android sends token to API
-> API validates everything
-> API returns result
```

---

# 🔐 4. Generate the QR Token on the Backend

The trusted QR token should be generated by the backend.

Do not ask Android to generate the trusted reservation token.

The intended flow is:

```text
Reservation created
-> API generates secure token
-> Token stored in Reservation
-> Token returned to Android
-> Android converts token into QR code
```

This keeps the trusted identifier under server control.

---

# 🎲 5. Generate an Unpredictable Token

The QR token should be difficult to predict.

Avoid values such as:

```text
1

2

3

A01-2026

USER123

RESERVATION5
```

Also avoid relying only on:

```text
MongoDB _id
```

as the parking-pass credential.

An attacker should not be able to guess another valid parking pass simply by understanding your ID pattern.

---

# 🔒 6. Use Node's Cryptographic Random Functionality

Node.js provides built-in cryptographic functionality through:

```text

```

You do not need to install another npm package for secure random token generation.

Research an appropriate secure random-data function such as:

```text
randomBytes()
```

The goal is to create a token that is:

```text
Random
Unique
Difficult to Guess
```

# ✅ 28. Validate the Reservation

Before check-in, the API should verify at least:

- QR token exists.
- Reservation exists.
- Reservation status allows check-in.
- Reservation is not cancelled.
- Reservation is not completed.
- Reservation has not already been checked in.
- Parking Area exists.
- Parking Bay exists.
- Reservation timing is appropriate.
- Requesting user has the manager role.

Depending on your final design, you may add additional rules.

# 🔐 47. Do Not Put Sensitive User Data Inside the QR Code

The QR code should contain only the value required to identify the reservation securely.


# 🧠 48. Why Use a Token Instead of Full Reservation Data?

Consider a QR containing:

```text

bay = A01
status = reserved
```

Someone could attempt to alter or recreate that data.

Instead:

```text
QR
-> random token
-> API
-> trusted reservation stored in MongoDB
```

The server remains responsible for the actual reservation information.

```text

```

This reinforces an important principle:

> A token existing is not enough. The server must also validate the current resource state.

# 🐛 Common Problems

## Scanner does not open

Check:

- Google Play services are available.
- Dependency has synced.
- Device/emulator meets the minimum SDK requirement.
- Scanner module is available.
- Scanner configuration is correct.

Use:

https://developers.google.com/ml-kit/vision/barcode-scanning/code-scanner

---

## Scanner opens but does not recognise the QR

Check:

- QR code is large enough.
- QR is not blurry.
- Screen brightness is sufficient.
- QR content is valid.
- Scanner is configured to recognise QR codes.

---

## Scanner module downloads on first use

Google Code Scanner uses functionality provided through Google Play services.

The scanner module may need to be downloaded before first use.

Ensure the device has internet access.

---

## QR displays but cannot be scanned

Check:

- QR dimensions.
- Contrast.
- Token is not blank.
- QR generator receives the complete token.
- You have not drawn UI elements over the QR image.

---

## QR scans but API says token is invalid

Compare:

```text
Scanned value
```

with:

```text
Reservation.qrToken
```

Check for:

- Extra whitespace.
- Truncated values.
- Wrong Reservation.
- Old QR image.
- Database token mismatch.

---

## Every scan returns `401`

Check the manager's:

```text
Firebase Authentication
```

and:

```text
Authorization header
```

The QR token is not a replacement for Firebase authentication.

Both may be required:

```text
Firebase Token
-> proves who the manager is

QR Token
-> identifies the Reservation
```

---

## Every scan returns `403`

Check:

```text
ParkSmart User role
```

The authenticated user may still be:

```text
driver
```

---

## Duplicate scan succeeds

Check that the API verifies current:

```text
Reservation.status
```

before changing it.

---

## Completed reservation can still be checked in

Review your permitted status transitions.

Check-in should only accept appropriate current states.

---

## Cancelled reservation still displays active QR

The Android screen should use the Reservation status when determining whether to display an active pass.

Do not check only:

```text
qrToken != null
```

---

## ZXing dependency compiles but generation fails

Check the ZXing documentation and verify that:

```text
QRCodeWriter
BarcodeFormat.QR_CODE
```

are being used with valid dimensions and a non-empty value.
